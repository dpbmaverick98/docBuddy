# DocsBuddy Ask API Documentation

Welcome to the DocsBuddy Ask API, a monetized Q&A service for documentation queries using the x402 payment protocol. This API allows you to ask questions about "privy" or "polymarket" projects and receive AI-powered answers based on indexed documentation.

**Note**: This endpoint requires payment via x402 (0.01 USD USDC on Base network) to access. You must integrate an x402-compatible client to handle payments seamlessly.

## Overview

- **Endpoint**: `POST /api/docsbuddy/ask/{project}`
- **Payment Required**: Yes, 0.01 USD USDC per request.
- **Supported Projects**: `privy`, `polymarket`
- **Model**: Fixed to `hf-k2-openai` (K2)
- **Protocol**: x402 for payments
- **Network**: Base
- **Asset**: USDC

The API answers questions using a RAG (Retrieval-Augmented Generation) pipeline, sourcing from relevant documentation chunks.

## Endpoint

```
POST /api/docsbuddy/ask/{project}
```

Where `{project}` is either `privy` or `polymarket`.

Base URL: `https://your-server-url` (replace with your deployed server URL).

## Request Format

Send a JSON POST request with the following body:

```json
{
  "question": "How do I implement authentication?",
  "context": "Optional: previous chat, user journey, or code snippet"
}
```

### Parameters

- **question** (string, required): The question to ask about the documentation.
- **context** (string, optional): Additional context like chat history or code snippets to improve answer relevance.
- **project** (path parameter, required): Must be "privy" or "polymarket" in the URL path. Invalid projects return 404 error.
- **model** (ignored): Internally locked to "hf-k2-openai".

### Headers

- **Content-Type**: `application/json`
- **PAYMENT-SIGNATURE** (required for paid access): Base64-encoded x402 payment signature. Generated by your x402 client after processing the 402 response.

## Payment Flow

This endpoint uses x402 for monetization. Clients must handle the payment protocol:

1. **Initial Request**: Send POST without payment headers.
2. **402 Response**: Server responds with 402 Payment Required, including payment instructions in the response body (scheme: exact, network: base, asset: USDC, amount: equivalent to 0.01 USD).
3. **Payment Creation**: Use an x402 client to create and sign the payment payload.
4. **Retry with Payment**: Resend the request with x402 payment headers.
5. **Verification & Access**: Server verifies payment via facilitator, proxies to backend, and returns the answer.
6. **Settlement**: On success, payment is settled, and settlement header is included.

### x402 Integration

Integrate an x402 client library (e.g., from Coinbase's x402 SDK or third-party wrappers). Example pseudocode:

```javascript
// Using a hypothetical x402 client
import { x402Client } from 'x402-client';

const client = new x402Client({
  network: 'base', // Base network
  wallet: yourWallet, // Connected wallet for payments
});

const response = await client.post('https://your-server-url/api/docsbuddy/ask/polymarket', {
  question: 'How to integrate payments?',
  context: 'User is on checkout page'
});

// Client automatically handles 402 -> payment -> retry
console.log(response.data); // Q&A answer
```

Without x402 integration, you'll receive 402 errors.

## Response

On success (after payment):

```json
{
  "answer": "To implement authentication, use the Privy SDK...",
  "sources": [
    {
      "doc_path": "/docs/auth.md",
      "doc_url": "https://docs.polymarket.com/auth",
      "doc_title": "Authentication Guide",
      "heading": "API Keys",
      "content": "Use API keys for server-side auth...",
      "score": 0.95
    }
  ],
  "confidence_score": 0.92
}
```

### Fields

- **answer** (string): AI-generated answer to the question.
- **sources** (array): List of documentation sources used, each with path, URL, title, heading, content snippet, and relevance score.
- **confidence_score** (float): Confidence in the answer (0-1).

### Headers

- **PAYMENT-RESPONSE** (on success): Base64-encoded settlement confirmation.

## Errors

### 404 Not Found
- Invalid project (not "privy" or "polymarket" in URL path).

### 400 Bad Request
- Malformed JSON.

### 402 Payment Required
- Missing or invalid `PAYMENT-SIGNATURE`.
- Returned with `PAYMENT-REQUIRED` header for payment details.

### 500 Internal Server Error
- Backend issues, facilitator failures, or verification errors.

## Examples

### cURL (Manual Payment Handling)

1. Initial request (will fail):
   ```bash
   curl -X POST https://your-server-url/api/docsbuddy/ask/polymarket \
        -H "Content-Type: application/json" \
        -d '{"question": "What is Polymarket?"}'
   ```
   Response: 402 with payment instructions.

2. After processing payment (replace `<signature>` with actual):
   ```bash
   curl -X POST https://your-server-url/api/docsbuddy/ask/polymarket \
        -H "Content-Type: application/json" \
        -H "PAYMENT-SIGNATURE: <base64-signature>" \
        -d '{"question": "What is Polymarket?"}'
   ```
   Response: JSON answer.

### JavaScript with x402 Client

```javascript
// Assuming x402Client handles payments
const answer = await x402Client.post('/api/docsbuddy/ask/polymarket', {
  question: 'How to trade on Polymarket?'
});
console.log(answer.data.answer);
```

## Rate Limits & Costs

- Payments are non-refundable; ensure question quality.
